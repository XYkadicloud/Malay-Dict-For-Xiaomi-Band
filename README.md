## 二、v0.11 改动（真机反馈 + 性能专项）

### 1. 搜索页模板塌陷（致命 bug）✅ 已修
**现象**：点「查词」后整页只剩一行提示文字。
**根因**：`search.ux` 第 35 行 `<list-item type="clr">` 后**漏了 `</list>`**，
导致后面的 `ctrlbar`、语言选择面板、候选行、结果区**全部被嵌套进输入 list 内部**，布局直接塌掉。
**修法**：补回 `</list>`。这类错误构建不报错（模板仍合法），只有真机能看出来。

### 2. 真分页：一次只取 10 条（不再一次收 50）✅
用户要求：「不要一搜索就搜 50 个词，分页，点下一页再搜不一样的 10 个」。

| | 旧（v0.9/v0.10） | 新（v0.11） |
|---|---|---|
| 单次解析条目 | **50** | **page×10 + 1**（第 1 页 = 11） |
| 页面展示 | 累积 `page×10` 条 | **只显示本页 10 条** |
| 翻页 | 切同一份数据 | 重新按需取（分片已在内存，不重复读文件） |
| 分页器 | 「加载更多（还有 N 条）」 | **‹ 上一页 / 下一页 › + 第 N 页 · 共 M 条** |

**关键实现**：`+1` 那条用于判断 `hasMore`，然后 `slice` 掉，不渲染。
端到端实测（`makan` / `me`）：每页零重复，第 2 页起全是新词。

### 3. 内存泄漏修复（隐性重启原因）✅
**发现**：`loader.releaseShards()` 原来**只清分片缓存**，
`zhCache`（中文桶）/ `pyCache`（拼音）/ `enCache`（英文表）**从来不释放**。
反复进出页面后常驻内存持续上涨 → 用久了变卡/重启。

**修法**：新增 `loader.releaseAll()`，四个缓存 + `pending` 队列 + LRU 顺序表全部清空；
`search.releaseShards()` 改为调用 `releaseAll()`。搜索页/测验页 `onHide`/`onDestroy` 都会调。

### 4. 设置页扩充（9 项）✅
用户授权 AI 自主决定，新增：

| 设置项 | 取值 | 作用 |
|---|---|---|
| 默认查询方向 | 中→马 / 马→中 / 英→马 | 打开搜索页即用该方向 |
| **每页结果条数** | 5 / 10 / 20 | **直接决定单次搜索内存占用**（怕闪退就调 5） |
| **每日学习每轮词数** | 5 / 10 / 15 | 控制一轮学习量 |
| 答错自动重练 | 开 / 关 | 测验答错的词放回队尾再考一次 |
| 按键振动 | 开 / 关 | 打字震动反馈 |
| 显示词性 | 开 / 关 | 结果里是否显示 n./v./adj. |
| 清空错词本 | — | 显示条数 |
| 清空查询历史 | — | 显示条数 |
| 清空收藏 | — | 显示条数 |
| 清空全部数据 | — | 收藏/历史/错词/设置一键重置 |

### 5. 每日学习优化 ✅
- **一轮结算页**：学完显示「本轮完成 · 学了 N 个词 · 加入生词本 M 个」+「再来一轮 / 重新随机」
  （旧版学完静默重载，用户以为卡住）
- **不重复抽词**：记住最近 30 个学过的词，下一轮排除；实测两轮**重叠 = 0**
- **按钮语义修正**：「换一个」→「没记住，下一个」（和「记住了」成对）
- **词库失败提示**：原来失败是空白页，现在提示「词库读取失败，请返回重进」
- **每轮词数**跟随设置（5/10/15）

### 6. 测验补上英语方向 ✅
用户问「为什么没做学习英语」——根因是 `makeQuestion` 里 `mode` 写死。
现在开始页有 **4 种模式**：马来语→中文 / 中文→马来语 / **英语→马来语** / 只练错题。
- `en2ms`：题干取 `entry.en`（如 `makan` → `to eat`），选项是马来语
- `en2ms` 的干扰项强制要求也有英文释义，避免出现空选项
- 干扰项不足 2 个时跳过该题（防止 2 选项题目）
- 收藏/错词本为空时，测验改为**从词库随机抽词**（否则「开始练习」永远空着）

## 四、v0.9 改动（依据优化提示词文档）

> 文档核心结论：**v0.8 的「结果卡显示完整详情」是闪退真凶** ——
> 15 条 × 完整详情 + 每条 6 个 JS 高度计算 = 内存峰值 + 布局重算。
> 需求「分页」和「点卡片才加载释义」其实是**同一个修复的两半**。

### ① 结果卡极简化

**改后**：每条只有「马来语词 + 词性」，**固定高度 56px**，
点卡片进 detail 页看完整释义。DOM 节点数从 ~15×9 降到 ~10×3。

### ② 分页（每页 10 条）

「**一次收集，前端切片**」：收集上限 `MAX_COLLECT = 50`，
页面只渲染 `page × 10` 条，底部「加载更多（还有 N 条）」按钮。

### ③ 复习测验 Latihan（新功能）

**单题模式** + **干扰项从正确答案所在分片取**（零额外 IO/内存）。
（v0.10 修复了推进逻辑与模式选择，见上。）

### ④ 跨语言模糊搜索

**根因在构建端**：搜「蓝」出不来 `biru`，是因为索引里没注册这个 key。

**解法**（`tools/build-dict.js`）——**两遍扫描**：
```js
// 第一遍：只注册整词（保证整词命中优先级最高）
reg(word, e.w)
// 第二遍：注册全部子串（「蓝色」→ 蓝 / 色）
for (a...) for (b...) reg(word.slice(a,b), ms, MAX_ZH_SINGLE)
```

> ⚠️ 必须分两遍。若在同一遍里做，遍历顺序会让「好吃」的马来语词
> 先占满「吃」的配额，导致 `吃 → makan` 被挤出（实测踩到的回归）。

**实测**：`蓝 → biru` ✅、`吃 → makan` ✅、`学习 → belajar` ✅

### ⑤ 性能收尾

| 项 | 状态 |
|---|---|
| `onDestroy` → `releaseShards()` | ✅ |
| `doSearch` 防连点锁 | ✅ |
| detail 页内存缓存（Map 上限 5） | ✅ |
| `MAX_RESULT` 15 → 10 | ✅ |

## 六、v0.7 修复：切方向搜索会重启

### 根因（两条，均为内存问题）

| # | 问题 | 数据 |
|---|---|---|
| 1 | **分片并发加载**：`Promise.all(letters.map(loadShard))` 一次解析最多 9 个分片 | 最大分片 140.7 KB |
| 2 | **索引整表加载**：`zh.txt` 1 MB，`JSON.parse` 后占 **5.7 MB 堆** | 叠加后超手环上限 |

### 对策（四层）

1. **分片加载改严格串行**：`loader.enqueue()` 全局队列
2. **索引全部拆小文件**：
   - 中文反查 → `zh-0.txt … zh-25.txt`（按首字码位 % 26）
   - 拼音 → `py-a.txt … py-z.txt`
   - 英文 → `en-a.txt … en-z.txt`
3. **LRU 收紧**：分片 2，拼音 2，中文桶 3，英文片 2
4. **离开页面释放**：`onHide` / `onDestroy` → `releaseShards()`

### 效果

```
start (index 已载)   heap=3.46MB
+ py-c (拼音候选)     heap=4.04MB   ← 只 +0.58MB（旧为 +5.7MB）
+ zh-5 (中文反查)     heap=4.12MB
+ 3 个词条分片         heap=4.32MB
+ en-e (英文索引)     heap=4.34MB   ← 峰值
```

**内存峰值 13.2MB → 4.34MB，降 67%。**

## 八、词库数据管线

### 三个数据源，按优先级合并

```
优先级高 ────────────────────────────────────────────► 优先级低
  手写种子(898)      中文维基词典(13,009)      Kaikki+ECDICT(9,924)
  人工校对            直接中文释义              英文释义
       │                    │                       │
       └────────┬───────────┴───────────┬───────────┘
                ▼                       ▼
        tools/build-dict.js（合并去重，字段互补）
                ▼
   src/assets/dict/{ms-*.txt, zh-*.txt, py-*.txt, en-*.txt, index.txt}
```

合并规则：**同词条时高优先级字段优先**，只补空缺不覆盖。

| 源 | 文件 | 条数 | 许可 |
|---|---|---|---|
| 手写种子 | `tools/seed-words*.js` | 898 | 自制 |
| 中文维基词典 | `tools/zhwiktionary-words.js` | 13,009 | CC BY-SA 4.0 |
| Kaikki + ECDICT | `tools/generated-words.js` | 9,924 | CC BY-SA 4.0 / MIT |

### 为什么用 dump 而不是 API

中文维基词典 API 有**严格限流**，批量抓 1 万词会在几百词后被 `HTTP 429` 掐断。
改用**官方 dump**（286 MB），一次下载、本地无限解析：

```bash
curl -L -o zhwiki-dump.xml.bz2 \
  https://dumps.wikimedia.org/zhwiktionary/latest/zhwiktionary-latest-pages-articles.xml.bz2
bunzip2 -dc zhwiki-dump.xml.bz2 > zhwiki-dump.xml
node tools/parse-zhdump.js < zhwiki-dump.xml
```

dump 里有 **13,040 个 `==马来语==` 章节**。

### 解析踩过的坑

| # | 坑 | 现象 | 修法 |
|---|---|---|---|
| 1 | dump 是**缩进格式** | 行首匹配 `<page>` 解析出 **0 页** | 改 `indexOf(...) >= 0` |
| 2 | 章节标题 3 种写法 | `kamu` 抓不到 | 正则容忍方括号 `\[*` |
| 3 | 部分词无二级标题 | `saya` 抓不到 | `parseByCategory()` 兜底 |
| 4 | 释义后跟其他语言段 | `buku` 混进满语 | 遇 `{{-xxx-}}` / `----` 截断 |
| 5 | XML 转义残留 | `&lt;br /&gt;` | 清洗实体 |
| 6 | 拼音表太小 | 20,572 词无拼音 | pinyin-pro 重生成（849 → 3,776 字） |

### 完整重建流程

```bash
cd ~/repo/malay-dict/devices/xiaomi-band-9/source/chinese

node tools/parse-zhdump.js < /root/ref/zhwiki-dump.xml   # 1) 维基词典
node tools/import-kaikki.js                              # 2) Kaikki+ECDICT
node tools/mk-pinyin.js                                  # 3) 拼音表
node tools/build-dict.js                                 # 4) 合并构建
node tools/verify-dict.js                                # 5) 验证
npm run build                                            # 6) 打包
```

## 十、体积与内存控制

### 体积（RPK 1.16 MB，上限 3 MB）

| 部分 | 未压缩 |
|---|---|
| `ms-*.txt` 26 个分片 | 1,120 KB |
| `py-*.txt` 23 个分片 | 526 KB |
| `zh-*.txt` 26 个桶 | 477 KB |
| `en-*.txt` 26 个分片 | 251 KB |
| 键盘资源（62 张图） | ~300 KB |
| 页面 JS + 图片 | ~250 KB |
| **合计** | **~2.9 MB** → RPK 压缩后 **1.16 MB** |

**若超限，按此顺序精简：**

1. `zh.txt` 的 `py` 去掉首字母缩写键（省约 250 KB，代价：`pg` 查不到「苹果」）
2. 砍掉 `generated-words.js`（Kaikki 源）→ 词条降到 13,009，省约 350 KB
3. 降低 `MAX_ZH2MS`（8）/ `MAX_EN2MS`（6）
4. 释义截断长度 60 → 40 字

### 内存（峰值 4.34 MB）

关键约束与做法：

- **绝不并发解析大文件**：`loader.enqueue()` 全局串行队列
- **索引按需分片加载**：拼音按首字母、中文按码位取模、英文按首字母
- **LRU 收紧**：分片 2 / 拼音 2 / 中文桶 3 / 英文片 2
- **查询结果封顶**：`MAX_RESULT` 15、`MAX_CANDIDATE` 12、`MAX_UNION` 30
- **离开页面释放**：`onHide` / `onDestroy` → `releaseShards()`

## 十一、Band 9 编码铁律（血泪教训）

1. **`for` 必须用具名变量**：`for="{{it in items}}"`，不能 `for="{{items}}"`。
   嵌套时内层 `$item` 覆盖外层 → 崩溃。
2. **`list-item` 的 `type` 必填**，相同 `type` 的 DOM 必须完全一致；
   **高度必须 JS 算好写进 `style`**，不会自适应。
3. **正文不要写 `lines: 1` / `ellipsis`**，否则长段落被截成一行。
4. **卡片宽度**：`width + margin-left + padding×2 ≤ 192`（例：156 + 12 + 12×2 = 192）。
5. **单位用 `px`**（`designWidth` = 物理屏宽 192），不用 `dp`。
6. **包内资源用绝对路径**：`/assets/dict/ms-a.txt`。
7. **词库文件必须用 `.txt` 扩展名**：Vela 读包内 `.json` 返回 `202 invalid file type`。
8. **运行时 API 全部 try-catch**（`vibrator` / `prompt` / `file.readText`）。
9. **Promise 必须有 `.catch()`**，否则白屏。
10. **`screentype.static="pill-shaped"`** 是胶囊屏键盘的正确参数。
11. **模板只能有一个根节点**，根节点上不要挂 `if`。
12. **★ 手环内存是硬约束**：不要并发解析多个大文件；大索引必须拆分按需加载。

## 十二、词库数据格式

每行 7 段，用 `|` 分隔：

```
马来语|词性|中文释义|释义(英/马)|例句|同义词|反义词
```

- `seed-*.js` 第 4 段是**马来文释义**（`ms`）
- `generated-words.js` 第 4 段是**英文释义**（`en`，由 `enCol: true` 标记）
- 词性：`n` `v` `a` `adv` `num` `pron` `prep` `conj` `int`

### 人工修正表

来源里的错误条目可在 `src/common/js/dict/search.js` 的 `ZH_OVERRIDE` 里覆盖：

const ZH_OVERRIDE = {
  '书': ['buku', 'kitab'],
  '书籍': ['buku', 'kitab']
}
