# 翻译功能原型（未集成）

> 状态：**原型验证完成，决定不做** · 归档日期 2026-10-15
> 脚本：`tools/translate-proto.py`（可直接运行）

---

## 一、为什么归档

用户提问「现在是不是还只是词典？想变成翻译软件呢」。

我做了可行性评估和原型验证，结论是**手环上做不了真翻译**，只能做「翻译助手」（词对词直译 + 明确标注）。用户随后决定**不做**，故仅归档原型与结论，供日后参考。

---

## 二、现状：它是词典，不是翻译软件

| 能力 | 现状 |
|---|---|
| 输入一个**词** → 出释义 | ✅ 有 |
| 输入 3 个字以上 | ❌ 打不进去（`pages/search/search.ux` 里 `maxlength="5"`） |
| 输入一句话 → 出译文 | ❌ 无（`search.js` 零分词代码，`grep sentence\|segment` = 0 命中） |

---

## 三、两个硬约束（决定天花板）

**约束 1：手环装不下模型**
真机实测**单块分配上限 1024KB**。连最小的 seq2seq 模型都装不下（最低几十 MB）。所以**神经网络翻译在手环上不可能**——这与「大肥鱼」聊天模型是同一个结论。

**约束 2：语料不够**
词典里多词短语仅 **2,703 条**（占 14.2%）。真翻译需要几万条句对，我们没有，也塞不进 1024KB。

---

## 四、原型实测结果

用 v0.15 的 27,129 个中文键，做「贪心最长匹配分词 + 逐词直译 + 最优释义选择」：

**能用的：**

| 输入 | 输出 | 评价 |
|---|---|---|
| 我吃苹果 | `ku makan epal` | ✅ 马来语母语者能懂 |
| 我要一杯水 | `ku nak secawan air` | ✅ 相当不错 |
| 这个多少钱 | `ini berapa harga` | ✅ 完全正确 |
| 请给我一杯咖啡 | `pinta bagi ku secawan kopi` | ✅ 能懂 |
| 我在学校吃苹果 | `ku berada sekolah makan epal` | ⚠️ 生硬但可懂（缺介词 `di`） |

**崩掉的：**

| 输入 | 输出 | 问题 |
|---|---|---|
| 你会说英语吗 | `lu yuran kata wira nahu morfin` | ❌ 「会」→`yuran`（会费）、「吗」→`morfin`（吗啡） |
| 他是我朋友 | `ia ya ku teman` | ⚠️ 「是」→`ya` 位置错 |

**覆盖率：高频中文词 2,767 个，词典覆盖 2,110 个 = 76.3%。**

## 五、若日后要做，缺 6 样

1. **分词** —— 最长匹配（原型已实现）
2. **译文组装** —— 拼接 + 空格规则
3. **语序调整** —— 中↔马都是 SVO，好办；但马来语定语后置、量词接数词
4. **虚词表** —— `吗 / 了 / 的 / 把 / 被` 是语法标记，**不能按字面译**（这是「吗」→`morfin` 的根因）
5. **形态学** —— 马来语是黏着语：`makan`（吃）有 **30 个派生**（`dimakan` 被吃 / `makanan` 食物 / `dermakan` 捐赠）；反向翻译必须还原词根
6. **输入框放开** —— `maxlength` 从 5 改到 60+

## 六、三档方案（当时给出的选项）

| 档 | 做法 | 效果 | 工作量 | 体积 |
|---|---|---|---|---|
| 1 | 只放开输入框，支持「整句直接命中短语」 | 固定说法能译 | 半天 | +0 |
| 2 ⭐ | 档 1 + 分词 + 逐词直译 + 虚词表 + 语序规则 | 简单句能懂，复杂句生硬 | 3~5 天 | +0.3MB |
| 3 | 加句对语料 / 外挂 API | 真翻译 | 大 | 手环装不下 |

推荐的是**第 2 档**，定位为「翻译助手」而非「翻译软件」。

---

## 七、失败显示原则（当时提议，未实现）

译不出的字**原样保留并标黄**，而不是硬塞一个错词。

理由：`你会说英语吗` 硬译成 `lu yuran kata wira nahu morfin`（含「吗啡」）比标成 `ku ?会 kata English ?吗` 糟糕得多——**宁可暴露未知，也不要输出错误**。
